# 10 — Data Store Generator

## Goal

Generate immutable Cubit state classes and Cubit classes from `data.yaml` for the counter app.

## Scope

- For each store declared in `data.yaml`:
  - Generate `<store_name>_state.dart` with an `Equatable` state class.
  - Generate `<store_name>_cubit.dart` with a `Cubit<State>` class.
- Map Metacode primitive types to Dart types for the MVP (`int`, `String`, `bool`, `num`).
- Initialize the cubit from the spec's `initialValue`.
- Generate a constructor and a `copyWith` method on the state.
- Generate one method per action referenced in behaviors (e.g. `increment()`).
- For the counter app, generate:
  - `CounterState` with `final int value`
  - `CounterCubit` with `void increment()`

## Acceptance criteria

1. Counter app data spec generates `lib/stores/counter_state.dart` and `lib/stores/counter_cubit.dart`.
2. Generated files use `equatable` and `flutter_bloc` correctly.
3. Generated code is syntactically valid Dart and compiles.
4. `CounterCubit().increment()` emits a new state with `value` incremented.
5. Unit tests assert generated Dart contains expected class/method names.

### Suggested API

```go
package flutter

func GenerateStores(ir *ir.IR, outDir string) error
```

- Reads actions referenced in behaviors from the symbol table to decide which methods to generate.
- If an action has no body specified, generate a placeholder method that throws `UnimplementedError`.

### Example generated output

```dart
// GENERATED BY METACODE - DO NOT EDIT BY HAND
// Source spec: data.yaml > counterStore

import 'package:equatable/equatable.dart';
import 'package:flutter_bloc/flutter_bloc.dart';

class CounterState extends Equatable {
  const CounterState({required this.value});

  final int value;

  CounterState copyWith({int? value}) {
    return CounterState(value: value ?? this.value);
  }

  @override
  List<Object?> get props => [value];
}

class CounterCubit extends Cubit<CounterState> {
  CounterCubit() : super(const CounterState(value: 0));

  void increment() => emit(state.copyWith(value: state.value + 1));
}
```

## Layering notes

- Depends on: IR, symbol resolution, behavior parser (to know which actions exist).
- Enables: AI wrapper generator can reference cubit methods.
- Action method bodies are simple for the MVP. Complex business logic will be delegated to the LLM in the wrapper generator milestone.
- Async strategies (local/remote) are deferred.
