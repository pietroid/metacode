# 11 — UI Widget Generator

## Goal

Generate dumb, stateless Flutter widgets from `ui.yaml`. Each top-level UI symbol becomes a `StatelessWidget` class.

## Scope

- Generate one Dart file per top-level UI symbol under `lib/pages/` (for pages) or `lib/widgets/` (for reusable components).
- Resolve syntax sugars:
  - Direct child -> canonical content prop.
  - List of items -> `children`.
  - Nested mapping -> constructor arguments.
- Treat unknown bare values as constructor parameters (variables).
- Assign `Key(symbolName)` to the top-level widget.
- Do **not** wire callbacks; leave them `null` or omitted. Callback wiring is the AI wrapper generator's job.
- For the counter app:
  - `HomePage` receives `counterValue` as a `String` constructor parameter and displays it in a `Text`.
  - `CounterButton` is a `FloatingActionButton` with no `onPressed`.

## Acceptance criteria

1. Counter app UI spec generates `lib/pages/home_page.dart` and `lib/widgets/counter_button.dart`.
2. Generated widgets are `StatelessWidget` classes with `const` constructors where possible.
3. `HomePage` exposes `required String counterValue` and displays it.
4. Generated Dart compiles.
5. Unit tests assert generated code contains expected widget names and parameters.

### Example generated output

```dart
// GENERATED BY METACODE - DO NOT EDIT BY HAND
// Source spec: ui.yaml > homePage

import 'package:flutter/material.dart';

class HomePage extends StatelessWidget {
  const HomePage({super.key, required this.counterValue});

  final String counterValue;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Text(counterValue),
      ),
    );
  }
}
```

## Layering notes

- Depends on: IR, UI catalog, symbol resolution, naming helpers.
- Enables: AI wrapper generator can import and wrap these dumb widgets.
- Keep the generator deterministic and catalog-driven. Custom widgets and dynamic lists are deferred.
- Styling props are intentionally ignored, per the spec.
