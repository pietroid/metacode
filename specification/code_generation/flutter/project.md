# Flutter Project Generation

This spec defines how a Metacode project is scaffolded into a production-grade Flutter application.

## Generated project structure

```
my_app/
├── lib/
│   ├── main.dart              # App entry point
│   ├── app.dart               # MaterialApp + top-level providers
│   ├── pages/                 # One file per page/widget from the UI spec
│   ├── stores/                # One file per store from the data spec (cubits/blocs)
│   ├── models/                # Data models from the model spec
│   ├── repositories/          # Data sources for local/remote strategies
│   └── widgets/               # Shared reusable widgets when needed
├── test/
│   ├── stores/                # Cubit/Bloc unit tests
│   ├── pages/                 # Widget tests
│   └── models/                # Model tests
└── pubspec.yaml
```

## Naming conventions

- **Files and folders**: `snake_case` (e.g., `home_page.dart`, `counter_store.dart`).
- **Classes**: `PascalCase` (e.g., `HomePage`, `CounterStore`, `CounterState`).
- **Public members**: `lowerCamelCase`.
- **Private helpers**: `_lowerCamelCase`.
- **Generated symbols**: match the UI/Data spec symbol names, converted to the appropriate casing for the target construct.

## `pubspec.yaml`

Generate a standard Flutter `pubspec.yaml`:

- `name`: derived from the project spec; must be a valid Dart package identifier.
- `description`, `version`, `publish_to: 'none'`.
- `environment.sdk: '>=3.0.0 <4.0.0'`.
- `dependencies`:
  - `flutter: sdk: flutter`
  - `flutter_bloc` for state management
  - `equatable` for value equality in states and models
  - Persistence packages only when required by the store strategy (`shared_preferences`, `hive`, etc.).
- `dev_dependencies`:
  - `flutter_test: sdk: flutter`
  - `flutter_lints: ^3.0.0`
  - `bloc_test` when BLoC/Cubit tests are generated
- `flutter.uses-material-design: true`.

## Entry point (`main.dart`)

```dart
void main() {
  runApp(const MyApp());
}
```

## App root (`app.dart`)

```dart
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: '<project name>',
      home: const HomePage(),
    );
  }
}
```

- If top-level stores/cubits exist, wrap `MaterialApp` in a `MultiBlocProvider` and inject them here.
- Keep `MaterialApp` minimal; theme/styling configuration comes from the style spec.

## Dependency injection

- Pass dependencies through widget constructors.
- Provide cubits/blocs with `BlocProvider` / `MultiBlocProvider`.
- Read them in descendants with `context.read<T>()` for actions and `BlocBuilder<T, TState>` / `BlocSelector<T, TState, ...>` for UI reactions.
- Avoid global mutable state, singletons, or `GetIt` unless strictly necessary for app-wide immutable configuration.

## Linting and code quality

- Follow `very_good_analysis`.
- Prefer `const` constructors and const literals.
- Use `super.key` shorthand in widget constructors.
- Keep widgets small, composable, and focused on a single responsibility.
- Add a generated-file header comment such as:
  ```dart
  // GENERATED BY METACODE - DO NOT EDIT BY HAND
  // Source spec: ui.yaml > homePage
  ```

## Assets and resources

- Declare assets, fonts, and flavors in `pubspec.yaml` only when the project spec references them.
- Prefer vector assets (SVG) or appropriately scaled PNGs; use `flutter_gen` only if the project opts into it.
